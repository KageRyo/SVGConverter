# SVGConverter v1.7.2 Release Preparation and Publication Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the compatible `v1.7.2` patch release containing the merged issue fixes, CI coverage, and Sonar disposition documentation.

**Architecture:** Prepare one release metadata commit on top of the verified `main` commit, pass it through the normal pull-request CI gate, then create the annotated version tag so the existing tag-driven workflow publishes Python and Windows artifacts.

**Tech Stack:** Python 3.13, `pyproject.toml`, setuptools, `build`, Twine, pytest/coverage, Ruff, Pyright, GitHub Actions, PyPI Trusted Publishing, GitHub CLI.

**Spec:** Merged GitHub issues [#50](https://github.com/KageRyo/SVGConverter/issues/50), [#51](https://github.com/KageRyo/SVGConverter/issues/51), [#52](https://github.com/KageRyo/SVGConverter/issues/52), and [`RELEASING.md`](../../../RELEASING.md).

## Global Constraints

- Release version is exactly `1.7.2` in both package version declarations.
- No runtime API or breaking behavior changes are introduced.
- Changelog date is `2026-09-17`.
- Use one release branch, one PR, required CI checks, squash merge, then an annotated `v1.7.2` tag.
- Do not force-reset the existing local `main`; it contains the local-only `.worktrees/` helper commit.
- Verify artifacts from the built wheel/sdist or a fresh environment, not the editable development install.
- SonarCloud S8707 findings remain an admin-only follow-up if their public status is still `OPEN`.
